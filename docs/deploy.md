# Сервер для жюри в Yandex Cloud

Одна машина в Yandex Cloud, открывается по голому IP через HTTPS, всё закрыто паролем. Код попадает на неё только через GitHub Actions: пуш в `main` → тесты → образы в Container Registry → выкат по SSH. Долгоживущих ключей от облака нигде нет.

## Как устроено

```
git push main ─► GitHub Actions ci.yml
                   ├─ make lint, make test, тесты на Postgres, фронт (tsc, vitest, сборка)
                   ├─ OIDC-токен прогона ─► Yandex Cloud ─► IAM-токен routing-ci (Workload Identity Federation)
                   ├─ образы backend и frontend с тегом коммита ─► Container Registry routing
                   └─ SSH deploy@IP (ключ хоста закреплён) ─► ~/app: compose-файлы, Caddyfile, .env
                                                             docker compose pull && up -d
                                                             /api/health через Caddy с паролем

Машина (Ubuntu 24.04, Ice Lake 2×50%, 4 ГБ, 30 ГБ HDD, статический IP)
  :80, :443 ─► Caddy ── HTTPS по IP (Let's Encrypt, профиль shortlived), пароль на всё
                 └─► frontend (nginx) ─► backend ─► Postgres
                                             └──► OSRM (граф в томе osrm-data)
```

Снаружи открыты только 22, 80 и 443 (группа безопасности). Порт 8000 фронта, Postgres и OSRM наружу не публикуются. Машина скачивает образы из реестра по IAM-токену своего сервисного аккаунта `routing-vm`: токен берётся из метаданных прямо перед `pull`.

| Файл | Зачем |
|---|---|
| `docker-compose.prod.yml` | надстройка над `docker-compose.yml` для сервера: образы из реестра вместо сборки, без порта 8000, плюс Caddy. Локальный `docker compose up` не изменился |
| `infra/caddy/Caddyfile` | HTTPS по IP, пароль, прокси на фронт |
| `.github/workflows/ci.yml` | тесты на каждый пуш и PR, выкат после пуша в `main` |
| `.github/workflows/osrm-graph.yml` | ручная сборка графа OSRM на машине |
| `.github/actions/vm-ssh` | общий шаг: `ssh vm` с закреплённым ключом хоста |
| `infra/yc/create.sh` | всё в облаке одной командой, повторный запуск ничего не пересоздаёт |
| `infra/yc/resize.sh` | доля ядер и память машины |
| `infra/yc/teardown.sh` | снести всё созданное |
| `infra/yc/cloud-init.yaml` | первая загрузка: пользователь deploy, Docker, swap, автообновления |
| `infra/github/set_secrets.py` | секреты и переменные GitHub |

## Первый запуск

Порядок важен: каждый шаг берёт то, что оставил предыдущий.

**1. Авторизовать yc.** `yc init`, папка `b1g640095ie8rkbcvrde`. Скрипты берут её сами (переменная `FOLDER_ID` в `infra/yc/lib.sh`), зона — `ru-central1-d`.

**2. Ключ для деплоя**, если его ещё нет:

```bash
ssh-keygen -t ed25519 -N '' -C deploy@beeline-routing -f ~/.ssh/beeline_routing_deploy
```

Публичная половина уедет на машину в cloud-init, закрытая — в секрет GitHub `VM_SSH_KEY`.

**3. Облако.**

```bash
infra/yc/create.sh               # или с --delete-old: заодно удалить старую машину transit-2gis с дисками
```

Скрипт создаёт реестр `routing`, сервисные аккаунты `routing-ci` (роль `container-registry.images.pusher` на реестр) и `routing-vm` (`container-registry.images.puller`), федерацию `routing-github` для GitHub OIDC с доступом только прогонам из `main`, статический IP, группу безопасности `routing-sg` и машину `routing`. Сеть берётся `default`; если её нет, создаётся своя. Идентификаторы печатаются и пишутся в `infra/yc/.state.env`.

Потом скрипт ждёт конца первой загрузки (обычно 3–6 минут) и снимает ключи хоста с вывода последовательного порта машины в `infra/yc/known_hosts`. Так ключ хоста закреплён из облака, а не с первого подключения вслепую. В конце он заходит на машину по SSH и проверяет, что Docker на месте. Оба файла в `.gitignore`.

**4. Репозиторий GitHub** — приватный `earlyr1/beeline-routing`, пушится только `main`. Токену для скрипта ниже нужны права на запись Secrets и Variables этого репозитория. Скрипт ищет его в `~/.config/github-mcp/token`, потом в `$GITHUB_TOKEN`, потом в файле `GITHUB_MCP_TOKEN` в корне (он в `.gitignore`).

**5. Секреты и переменные.**

```bash
uv run infra/github/set_secrets.py
```

Спросит пароль жюри без эха, дважды. Без клавиатуры — `BASIC_AUTH_PASSWORD` в окружении или одной строкой через `--password-stdin`; в аргументах пароля нет нигде. Логин по умолчанию `jury` (`--basic-auth-user`). Скрипт печатает только имена, значения — никогда. `--dry-run` показывает, что будет задано, ничего не отправляя.

| Что | Вид | Откуда |
|---|---|---|
| `YC_SA_ID`, `YC_REGISTRY_ID`, `VM_HOST` | переменные | `infra/yc/.state.env` |
| `TLS_MODE` | переменная | `acme`, или `--tls-mode internal` |
| `VM_SSH_KEY`, `VM_KNOWN_HOSTS` | секреты | `~/.ssh/beeline_routing_deploy`, `infra/yc/known_hosts` |
| `YANDEX_MAPS_API_KEY`, `YANDEX_GEOCODER_API_KEY`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | секреты | `.env` в корне; пустые пропускаются |
| `BASIC_AUTH_USER`, `BASIC_AUTH_HASH`, `BASIC_AUTH_PASSWORD` | секреты | пароль жюри: хэш bcrypt для Caddy, сам пароль — для проверки после выката |
| `POSTGRES_PASSWORD` | секрет | генерируется один раз; если уже есть, не трогается |

Пароль Postgres генерируется только при первом запуске: база на машине создаётся с ним, и новый пароль её бы сломал. Он из букв, цифр, `-` и `_`, потому что подставляется в `DATABASE_URL` без экранирования. `TWOGIS_API_KEY` на сервер не едет: матрицы транспорта уже лежат в образе backend.

**6. Пуш.**

```bash
git remote add origin git@github.com:earlyr1/beeline-routing.git
git push -u origin main
```

Workflow `ci` прогонит тесты (дольше всего идёт `make test`: локально это 6,5 минуты, на раннере GitHub дольше), соберёт образы и выкатит их. На первом выкате Caddy получает сертификат, а backend применяет миграции, поэтому проверка здоровья ждёт до 5 минут.

**7. Граф дорог.** Actions → `osrm-graph` → Run workflow на `main`. Без графа сервис работает, но считает расстояния по прямой. Сборке тесно в 4 ГБ, поэтому на её время лучше поднять память:

```bash
infra/yc/resize.sh 50 8      # до запуска osrm-graph
infra/yc/resize.sh 50 4      # после
```

Workflow качает выгрузку OpenStreetMap по Центральному ФО (876 МБ), вырезает Москву с областью, строит граф в томе `osrm-data`, перезапускает `osrm` и проверяет маршрут по Москве. Повторный запуск ничего не пересобирает.

**8. Проверка.** Открыть `https://<IP>/`: браузер спросит логин и пароль, потом откроется интерфейс. С терминала:

```bash
curl -u jury https://<IP>/api/health          # спросит пароль; ответ {"status":"ok"}
```

Ключ Яндекс Карт ограничен по HTTP Referer значением `localhost`. Чтобы карта Яндекса открылась на сервере, в кабинете разработчика к ограничению нужно добавить IP машины. Если кабинет IP не примет — удалить секрет `YANDEX_MAPS_API_KEY` и перезапустить выкат: без ключа фронт показывает карту OpenStreetMap.

## HTTPS по IP

Let's Encrypt выдаёт сертификаты на IP-адрес только в профиле `shortlived`: сертификат живёт около шести дней, Caddy продлевает его сам. Профили ACME в Caddy пока помечены как экспериментальные; образ `caddy:2.11-alpine` — это Caddy 2.11.4 или новее. Проверка идёт по http-01 на 80-м порту или по tls-alpn-01 на 443-м, поэтому оба должны быть открыты всегда, а не только при выпуске.

Браузер и curl не шлют SNI, когда адрес — IP. Внутри контейнера адрес назначения — внутренний адрес Docker, не публичный, и без подсказки Caddy не знает, какой сертификат отдать. Подсказка — `default_sni` в Caddyfile; без неё рукопожатие не проходит (проверено локально).

Сертификаты и ключ аккаунта ACME лежат в томе `caddy-data` и переживают передеплой. Это важно: у Let's Encrypt лимит — пять сертификатов на один и тот же набор имён за семь дней.

Если Let's Encrypt недоступен или упёрлись в лимит, есть запасной режим — свой CA Caddy:

```bash
uv run infra/github/set_secrets.py --tls-mode internal   # Enter вместо пароля — BASIC_AUTH_* не меняются
```

Потом перезапустить выкат (Actions → `ci` → Run workflow). Браузер покажет предупреждение о сертификате, дальше всё работает так же. Вернуть — `--tls-mode acme` и снова выкат.

### Хэш пароля и знак $

Хэш bcrypt выглядит как `$2b$12$…`, и compose принимает всё после `$` за имя переменной. В `.env` на машине деплой пишет каждое значение в одинарных кавычках: внутри них compose ничего не подставляет, а подставленное в `docker-compose.prod.yml` значение повторно не разбирает. Так хэш доходит до Caddy целым. Проверено: без кавычек и в двойных кавычках хэш обрезается до `$2b$12`, и пароль перестаёт подходить. Поэтому значения с одинарной кавычкой или переводом строки деплой не пропускает, а `set_secrets.py` отвергает их заранее.

## День защиты

Машина работает на 50% гарантированной доли ядер: в спокойные дни этого хватает, но пересчёт плана под нагрузкой может упереться в лимит. Накануне защиты:

```bash
infra/yc/resize.sh 100 4
```

После защиты — `infra/yc/resize.sh 50 4`. Каждый вызов останавливает машину на минуту-две; IP, диск и тома сохраняются, контейнеры поднимаются сами. Разница в цене — около 24 ₽ за сутки.

## Откат

Actions → `ci` → прогон нужного коммита → Re-run all jobs. Прогон пройдёт тесты и выкатит образы с тегом того коммита (сборка возьмёт слои из кэша). Базу откат не трогает: если между коммитами появилась миграция, старый код увидит уже новую схему.

Руками, если GitHub недоступен:

```bash
ssh -i ~/.ssh/beeline_routing_deploy -o UserKnownHostsFile=infra/yc/known_hosts deploy@<IP>
cd ~/app
sed -i "s/^TAG=.*/TAG='<sha коммита>'/" .env
curl -s -H Metadata-Flavor:Google http://169.254.169.254/computeMetadata/v1/instance/service-accounts/default/token \
  | jq -r .access_token | docker login --username iam --password-stdin cr.yandex
docker compose -f docker-compose.yml -f docker-compose.prod.yml pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --no-build
```

Следующий выкат из GitHub перепишет `.env` целиком.

## Повседневное

| Задача | Как |
|---|---|
| Сменить пароль жюри | `uv run infra/github/set_secrets.py`, новый пароль, потом Run workflow у `ci` |
| Поменять ключ карт или модели | поправить `.env` локально, `set_secrets.py` (Enter вместо пароля), Run workflow у `ci` |
| Логи | `ssh … deploy@<IP> 'cd app && docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f --tail 100 backend'` |
| Лог первой загрузки | `sudo cat /var/log/cloud-init-output.log` на машине |
| Место на диске | после каждого выката старые образы удаляются, откат скачает свой тег заново |

Выкаты и сборка графа не пересекаются: у обоих workflow общая группа `concurrency`.

У job деплоя нет `environment:` и не должно появиться. С ним поле `sub` в OIDC-токене GitHub становится `repo:…:environment:…`, а федерация в Yandex Cloud доверяет только `repo:earlyr1/beeline-routing:ref:refs/heads/main`. Прогоны из других веток и pull request в облако не попадают вовсе.

Если с машины не открывается Docker Hub (`postgres`, `caddy` не скачиваются), в `/etc/docker/daemon.json` добавляется `"registry-mirrors": ["https://mirror.gcr.io"]` и `sudo systemctl restart docker`.

## Сколько стоит

Цены с НДС: vCPU Ice Lake — 0,52 ₽/ч при доле 20%, 0,75 ₽/ч при 50%, 1,24 ₽/ч при 100%; RAM — 0,33 ₽ за ГБ в час; публичный IP на работающей машине — 0,26352 ₽/ч; network-hdd — 0,0048 ₽ за ГБ в час; реестр — 0,004575 ₽ за ГБ в час. Первые 100 ГБ исходящего трафика в месяц бесплатны, жюри столько не выкачает.

В обычном режиме из 3,23 ₽/ч ядра — 1,50, память — 1,32, IP — 0,26, диск — 0,14. Остановленная машина стоит 0,75 ₽/ч, и 0,60 из них — статический IP: без работающей машины он дороже, чем с ней (0,6039 против 0,26352 ₽/ч). Образы в реестре — единицы рублей в месяц (3,29 ₽ за гигабайт).

С 23.09 по 30.10 — 37 суток — выходит около 2 900 ₽: машина в обычном режиме, сутки защиты на 100%, пара часов сборки графа на 8 ГБ, реестр.
