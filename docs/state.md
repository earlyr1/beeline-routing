# Где сервис хранит состояние

Семь мест, и у каждого своя причина. Короткий ответ на вопрос «что переживёт перезапуск»: день диспетчера переживает, кэши переживают, скорость работы — нет.

| Где | Что там | Переживает перезапуск backend | Переживает пересборку образа | Переживает чужую машину |
|---|---|---|---|---|
| Postgres, том `pg-data` | день диспетчера целиком | да | да | нет, база своя у каждого |
| Том `backend-cache` | кэш матриц OSRM и геокодера | да | да | нет, наполняется заново |
| Том `osrm-data` | граф дорог Москвы и области | да | да | нет, собирается шагом `osrm-prepare` |
| Образ backend | бандлы, ночные планы, матрицы 2ГИС, кэш адресов, конфиг | да | обновляется из репозитория | да |
| Память процесса backend | разобранный день, матрица дороги, пул решателя, блокировки | нет, поднимается из базы | нет | нет |
| Браузер | номер открытого дня | да | да | нет, у каждого браузера свой |
| `.env` на машине | ключи Яндекс Карт, 2ГИС и LLM | да | да | нет, и в git не попадает |

## 1. День диспетчера — Postgres

Таблицы заводит миграция `backend/migrations/0001.day-state.sql`, следующие миграции её правят (`0003` снесла таблицу отметок звонков `agreed_windows`: отметка стала событием шкалы). Применяет их backend на старте (yoyo).

| Таблица | Что в ней | Когда пишется |
|---|---|---|
| `days` | входные данные дня (заявки, бригады, офис, план диспетчеров), отчёт разбора, статус, текущее время, счётчики номеров | при загрузке файла или открытии региона, дальше при каждом сдвиге часов |
| `timeline_entries` | события шкалы: что произошло, во сколько, какой вариант выбран, адреса геокодера события; среди них и что сказали клиенту по телефону (событие «Коммуникация») | при добавлении события, выборе варианта и отметке ✓ во вкладке «Коммуникации» |
| `plans` | **готовые планы**: снимок после каждого шага шкалы, ключ — принятые события плюс токен шага | после каждого расчёта, в том числе фонового предподсчёта |
| `proposals` | предложения помощника и их статусы | при обращении к помощнику и при применении предложения |

Планы именно хранятся, а не выводятся заново. Поиск OR-Tools ограничен по времени, поэтому повтор того же расчёта даёт другие маршруты: «восстановим день, повторив события» показало бы диспетчеру план, которого он не видел и, возможно, уже обсудил с бригадой другой. Поэтому при подъёме дня решатель не запускается ни разу — читаются сохранённые снимки.

Размер: снимок плана дня «Восток» — около 56 КБ утром и 67 КБ после события; день с двумя десятками событий занимает единицы мегабайт. Матрица дороги (278 КБ на шаг) в базу не едет: это чистая функция от точек дня, она пересобирается из кэша матриц.

Дней в базе держится 20, в памяти процесса — 8: самые давние вытесняются, вкладок с ними всё равно никто не держит открытыми. Вытесненный из памяти день поднимается из базы при первом обращении.

## 2. Кэш матриц и геокодера — sqlite в томе `backend-cache`

Файл `/cache/cache.sqlite`, одна таблица ключ-значение (`backend/app/geo/kvcache.py`). В нём ответы OSRM на матрицы точек и ответы геокодера. Сейчас около 11 МБ.

Это чистый кэш: удаление ничего не ломает, только первый расчёт дня станет медленнее. В Postgres он **не** переехал намеренно — тогда офлайн-скрипты (`prepare`, `night_plan`, `transit_matrix`), которые гоняются на хосте руками, потребовали бы поднятой базы.

## 3. Граф дорог — том `osrm-data`

Собирается один раз шагом `docker compose --profile prepare run --rm osrm-prepare`: выгрузка OpenStreetMap по ЦФО, вырезка Москвы и области, сборка графа. Без него сервис считает расстояния по прямой и честно пишет в отчёте `matrix_source: haversine`.

## 4. Данные, которые едут в образе

Копируются в образ backend при сборке, поэтому одинаковы на любой машине:

- `data/bundles/<регион>/bundle.json` — подготовленный день региона;
- `data/bundles/<регион>/night_plan.json` — утренний план, найденный ночным поиском;
- `data/transit/<регион>.json` — матрицы общественного транспорта;
- `data/geocode_cache.json` — кэш адресов, чтобы демо не ходило в сеть;
- `backend/config/*.yaml` — правила синтеза, нормативы, коэффициенты пробок.

Отсюда следует правило, которое легко забыть: **пересчитали что-то из этого на хосте — пересоберите образ** (`make rebuild`), иначе сервис продолжит показывать старое.

## 5. Память процесса backend

В памяти живёт то, что дешевле пересобрать, чем хранить: разобранный день, матрица дороги, пул процессов решателя, блокировки, счётчики фонового предподсчёта. Перезапуск это теряет и восстанавливает из базы при первом обращении к дню.

Отсюда ограничение: **один процесс backend на одну базу**. Второй процесс, подняв тот же день, разошёлся бы с первым в памяти. Для прототипа это записано в `README.md`; в промышленной версии за это отвечала бы аренда дня (lease) с продлением.

## 6. Браузер

В `localStorage` лежит ровно одно: номер открытого дня (`routing.datasetId`). Благодаря ему перезагрузка вкладки возвращает тот же день, а не пустой экран. Всё остальное — план, события, согласованные окна — приходит с сервера.

Отмена заявки, которая 5 секунд ждёт в уведомлении, не хранится нигде, кроме памяти вкладки: до конца отсчёта на сервер она не ушла, и перезагрузка страницы или смена дня её отбрасывают, а не отправляют.

Раньше там же лежали отметки «Согласовано» из вкладки «Коммуникации», и это была настоящая дыра: отказ клиента был событием сервера, а состоявшийся разговор — записью в чужом браузере. Теперь они в Postgres, и их видит любой, кто откроет этот день.

## 7. Ключи

`.env` в корне: ключ Яндекс Карт, ключ 2ГИС, доступ к LLM помощника, учётные данные Postgres (у них есть рабочие значения по умолчанию, править файл ради них не нужно). Файл в `.gitignore` и в образ не попадает: контейнер получает переменные из `env_file`.

## Что это значит на практике

- **Перезапустили backend** (`make rebuild`, падение, обновление) — день на месте: тот же план, та же шкала, то же время на часах, те же отметки звонков.
- **Удалили том `pg-data`** — дни пропали, данные и планы регионов целы: открыли регион кнопкой, и день собрался заново.
- **Удалили том `backend-cache`** — ничего не потеряно, первый расчёт дня дольше обычного.
- **Клонировали репозиторий на чужой ноутбук** — регионы, ночные планы и матрицы уже внутри; нужны только Docker и один раз собранный граф OSRM.
