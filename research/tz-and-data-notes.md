# ТЗ Билайн Бизнес (ЛЦТ) и датасет: что реально дано

## ТЗ (pdf, 9 стр.) — ключевое
- Прототип, не промышленная система. Демо 5-7 минут: загрузить данные → спланировать → карта → объяснить одну заявку → одно событие (срочная / отмена / инженер недоступен) → перепланировать → показать diff → сравнить с базовым вариантом.
- Три обязательных группы ограничений: навык (1 из 3: Локальные работы / Подключение и дозаказы / Аварийные), время (окно заявки + смена инженера + путь + длительность), ресурс (тип транспорта: Автомобиль / Пешеход / Велосипед / Общественный транспорт). Оборудование — опционально.
- Две обязательные метрики: число уникальных задействованных исполнителей (минимизировать) и пробег по каждому исполнителю + суммарно.
- Базовый вариант задан точно: заявки по порядку поступления, первому по порядку во входных данных доступному инженеру, порядок посещения = порядок назначения, без глобальной оптимизации. Его надо реализовать 1:1 для сравнения.
- Маршрут начинается в стартовой точке инженера, возврат не нужен.
- Входные сущности: Заявка(ID, коорд/адрес, длительность мин, окно, приоритет Обычная/Срочная, навык, транспорт?), Инженер(ID, старт, смена, 1-3 навыка, транспорт), Событие(тип, время, ID; для срочной — полная заявка).
- Неназначенные заявки: явно + причина на русском (нет свободных на время / нет навыка / нет транспорта / не влезает в окно/смену).
- Доп. уровень: сравнение нескольких вариантов, ручное переназначение, несколько сценариев, прогноз опозданий.
- Оценка: подход 25%, техника 30%, соответствие 20%, эффективность+UX 15%, презентация 10%. README-воспроизводимость проверяют.

## Датасет (zip, cp1251, `;`): 3 региона × 2 файла
- Регионы: Восток (66 заявок, 12 бригад), Юго-восток (83, 12), Югоцентр (56, 11). Один день 17.08.2026.
- «Контрольное распределение» = реальное распределение диспетчерами: колонки Заявка, Тип BK, Статус BK, Тип HD, Начало, Окончание, Район, Адрес (с кв.), Бригада, [Подключение FMC/FTTB], Гигабит.
- «Синтетические данные» = те же строки с новыми ID, без бригады/статуса/квартиры + 3 мусорные строки в конце: две пустые и «Адрес Офиса» с адресом офиса региона (= стартовая точка инженеров!).
- Окна: 2-часовые слоты 10:00-22:00; аварии («Глобальная проблема» / «Авария») с окном 0:01-23:59.
- Статусы: Выполнена, Отправлена, В пути, В работе, Отменена (10+6+5), Просрочена (4+6+0). Отмены и просрочки = готовые сценарии перепланирования и метрика «реальные диспетчеры опоздали N раз».
- Маппинг на навыки ТЗ: Локальная заявка → Локальные работы; Подключение + Дозаказ → Подключение и дозаказы; Глобальная проблема → Аварийные.
- Профиль навыков бригад восстанавливается из контрольного распределения (большинство 2 типа, часть 3-4, 5 бригад с одним).
- НЕТ: длительностей, координат, файла инженеров, транспорта, смен, приоритетов. Всё это надо синтезировать по правилам ТЗ и задокументировать допущения.
- Гео-ловушки: Юго-восток включает Каширу (16), Ступино (4), Домодедово (12) — это 50-100 км от Москвы. Район «GPON Даниловский». Дубли ID в синтетике (Восток: 68 уникальных на 69 строк).
